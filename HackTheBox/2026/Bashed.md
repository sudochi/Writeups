# Bashed – Writeup (Easy)

**Machine:** Bashed  
**Difficulty:** Easy  
**Tech Used:** Nmap, Dirb, PHPBash, Linux privilege escalation, Reverse Shell, Cron  
**Objective:** Demonstrate web enumeration, exploitation of an exposed web shell, user enumeration, and privilege escalation to root.

---

## Overview

Bashed is an easy-level HackTheBox machine focused on web enumeration and Linux privilege escalation. The initial Nmap scan revealed that only port 80 was open. After navigating to the website, there was not much information available, so I performed directory enumeration using Dirb.

Dirb discovered a `/dev` directory containing two PHP files. One of these files, `phpbash.php`, provided access to a web-based Bash shell. This gave me command execution on the target as the `www-data` user.

From there, I enumerated the system and discovered the `arrexel` and `scriptmanager` users. The `arrexel` home directory contained the user flag. I then discovered that `www-data` could execute commands as `scriptmanager` without a password. After escalating to `scriptmanager`, I discovered a `/scripts` directory containing a Python script that was executed by root every minute. Modifying this script allowed me to obtain a root shell and retrieve the root flag.

### User Flag

I began enumerating the filesystem and navigated to /home:

```bash
cd /home
ls
```

There were two user directories:

```bash
arrexel
scriptmanager
```

I navigated into the arrexel directory:

```bash
cd /arrexel
ls
```
A user.txt file was present. I retrieved the flag using:

```bash
cat user.txt
```
This successfully provided the user flag.

### Privilege Escalation

After obtaining the user flag, I checked the sudo permissions available to the current account.

The results showed that www-data could execute commands as the scriptmanager user without entering a password.

<img width="506" height="65" alt="sudo -l" src="https://github.com/user-attachments/assets/7a406ec7-d29f-4a48-8b42-9f99d2190828" />

I prepared a reverse shell on my attacking machine and sent the required script to the target. I then started a listener on my local machine and executed the reverse shell.

Once the connection was received, I upgraded the shell to make it more interactive.

I then switched to the scriptmanager account using:

```bash
sudo -u scriptmanager -i
```
This gave me an interactive shell as scriptmanager.

While enumerating the filesystem as scriptmanager, I noticed a /scripts directory that was only accessible by this user.

<img width="480" height="248" alt="gained shell and changed to user" src="https://github.com/user-attachments/assets/569aa65e-39ac-4571-9b99-f99bd33233bf" />

### Privilege Escalation to Root

I navigated to the directory:

```bash
cd /scripts
ls
```

Two files were present:

```bash
test.py
test.txt
```

The test.txt file appeared to contain the output generated by test.py, which suggested that the Python script was being executed automatically.

I checked the scheduled tasks using:

```bash
crontab -l
```

The enumeration showed that the Python script was being executed every minute by the root user.

Since I had permission to modify test.py, this presented a privilege escalation opportunity. Any commands added to the script would execute with root privileges when the cron job ran.

I modified test.py to include a reverse shell that would connect back to my attacking machine.

I then started a listener on my local machine and waited for the cron job to execute.

After a few minutes, the reverse shell connected back to my listener, this time running with root privileges.

I confirmed the privileges with:

```bash
whoami
```

The result showed:

```bash
root
```

With root access, I navigated to the root user's home directory and retrieved the final flag:

```
cd /root
cat root.txt
```

## Conclusion

Bashed demonstrates how multiple simple misconfigurations can be chained together to obtain complete system compromise.

The initial Nmap scan identified an HTTP service on port 80. Directory enumeration with Dirb then uncovered the /dev directory, which contained an exposed PHPBash script. Accessing phpbash.php provided command execution as www-data.

From the initial foothold, basic Linux enumeration revealed the available user accounts and allowed me to retrieve the user flag from /home/arrexel. Further enumeration of sudo permissions showed that www-data could execute commands as scriptmanager without a password, providing the next step in the attack chain.

As scriptmanager, I discovered the /scripts directory and identified a Python script that was being executed every minute by root. Because I had permission to modify the script, I was able to add a reverse shell and wait for the root cron job to execute it. This ultimately provided a root shell and allowed me to retrieve the root flag.

The main techniques demonstrated by this machine were:
  - Full TCP port enumeration with Nmap
  - Web directory enumeration with Dirb
  - Identifying an exposed PHPBash web shell
  - Obtaining command execution as www-data
  - Linux filesystem enumeration
  - Sudo privilege escalation
  - Reverse shell usage
  - Identifying a root-owned cron job
  - Exploiting a writable script executed by root
  - Obtaining a root shell

Overall, Bashed is a good demonstration of how many simple misconfigurations can be used together to progress from an exposed web application to complete root-level exploitation.
